# 損傷狀態編碼器（damage-state encoder）

取代 GRU extractor（`phase1_extractor/`）當生成器條件的候選。動機見 [eval/condition_g.md](eval/condition_g.md)：GRU 的 g 是為了預測力而學的，將近一半的變異是加載正負號，雙向結構讓 g_t 混入了未來，Δg 量到的主要是方向翻轉，柱子特性和時間狀態也糾纏在一起。

**狀態（2026-10-23）**：兩個版本都已訓練完並做過篩選（§5、§7），還**沒有**接進任何生成器。

| 版本 | 輸入 | run |
|---|---|---|
| A（token） | 每個半循環一個 token（9 個特徵）＋7 個無因次描述 | `results/DamageStateEncoder/2026-10-23_21-46-11/` |
| B（逐點） | GRU extractor 原本的逐點輸入（17 個 column info、drift、模擬力）＋s 也讀 17 個 info；加上逐點實驗力損失 | `results/DamageStateEncoder/2026-10-23_22-13-12/` |

## 1. 資料

每條迴圈都重新取樣成「每個半循環 30 個點」：160 根柱的長度都是 30m+1，drift 反轉都落在 30 的倍數上（4423 個反轉裡只有 2 根柱各差 1 個點）。影像的 timestep 也都是 30 的倍數。所以：

- **token k**（k = 1..m）是 [30(k−1), 30k] 這一段，代表峰值 30k 的狀態。timestep 為 0 的影像（加載前）用全零狀態。
- **輸入**來自模擬迴圈（推論時已知），**目標**來自實驗迴圈。力除以該柱最大的 |模擬力|，和 `HystereticDataset` 相同。
- 實驗和模擬的 drift 在 57 根柱上不是逐點相等，但最大相對差只有 0.02%（捨入誤差），可以直接逐點對齊。

| 類別 | 內容 |
|---|---|
| token 特徵（9 個，模擬迴圈） | 峰值 drift、\|峰值 drift\|、峰值力、\|峰值力\|、該段消散能量、割線勁度、已到達的最大 drift、累積能量、正負號 |
| 靜態描述（7 個＋破壞型態 one-hot） | 軸壓比 n、L/h、ρ、ρ_t、f'c、ρ·f_yl/f'c、ρ_t·f_yt/f'c（`depth` 欄假設為加載方向，沒有驗證） |
| 回歸目標（5 個，實驗迴圈） | \|峰值力\|、強度比（峰值力 / 歷史最大）、勁度比（K / K₀）、累積能量、\|殘餘 drift\| |
| 分類目標 | 是否已破壞（強度比 < 0.8） |
| 有效遮罩 | 峰值 drift 小於歷史最大 10% 的 token（迴圈最後回到 0 的那段）不計入回歸損失 |

程式：`src/data/damage_state.py`。

## 2. 模型

```
靜態描述 + 破壞型態 ──► MLP ─────────────────────────► s（64 維）
                                                         │
token k ──► Linear(9→128) ──[ ‖ s ]──► 單向 GRU（2 層）──► z_k
                                                         │
                                  [z_k ‖ s] ──► 回歸頭（5）、破壞頭（1）
```

- 單向：z_k 只看到第 k 個峰值為止。
- 鏡像增強：訓練時以 0.5 的機率把整條迴圈的帶號特徵（峰值 drift、峰值力、正負號）同時變號，目標不變。帶號特徵的標準化平均固定為 0，所以鏡像在標準化後仍然精確。
- 程式：`src/model/damage_state_encoder.py`，訓練：`train_damage_encoder.py`。

## 3. 訓練

- 切分：`id_list_big.json` 的 train / val，**拿掉 6 根影像柱**（R315、R330、R615、R1015、R307、CTR1），剩 124 / 30 根。不做交叉驗證，影像柱也不參與 checkpoint 挑選。
- 損失：回歸 MSE（標準化單位，等權重）+ 0.5 × 破壞 BCE；AdamW；early stopping（patience 100）看 val loss。
- 在 CPU 上（2 個執行緒）每次約 1 分鐘。

## 6. 版本 B：原本 GRU 的輸入

- 輸入與 `phase1_extractor` 完全相同：`gru_inputs()` 直接用 `HystereticDataset`（同樣的 `statistics_big.csv` 標準化），每點 19 個特徵。單向 GRU 讀完整條序列，影像幀取該 timestep 的 z_t（timestep 0 也有狀態）。
- 損失多了逐點實驗力 MSE（權重 1）；峰值處的損傷目標不變。s 讀 7 個無因次描述＋17 個 info＋破壞型態（`--static_info 1`）。
- 超參數沿用版本 A 選出的（hidden 256、dropout 0.3、weight decay 1e-2、lr 3e-4）。GPU 訓練，最佳在第 109 個 epoch（210 停止）。val：逐點力 MSE 0.0114，峰值處各目標的 MSE 和版本 A 相近（勁度比 0.42 稍差）。
- 用法：`train_damage_encoder.py --input_mode points`（預設），或 `qsub -v MODEL=damage_state job/HysteresisPrediction/train_hysteresis.sh`。

**加載正負號回來了。** 逐點力是帶號的，要預測它，z_t 就必須知道目前的加載方向；鏡像增強只讓網路等變（跟著翻轉），不會讓它不變。處理方式：推論時把原始和鏡像迴圈各跑一次，取 z_inv = (z(x) + z(−x)) / 2，只保留和方向無關的部分，不需要重訓。

2. **先改善編碼器**：靜態輸入加上 GRU 原本的 17 個參數；在 token 之間加逐點的力損失；或把累積量當成直接輸入。每次嘗試只要幾分鐘，但仍然只能用探針判斷。
3. **混合方案**：保留舊 g 的方向，加上編碼器的 s 當第二個條件，只解決柱子特性的問題。
