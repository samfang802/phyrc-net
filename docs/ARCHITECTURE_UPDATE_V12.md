# ARCHITECTURE_UPDATE_V12

v12 = v11_app（v11 條件 + 每序列 8 維外觀碼）+ 一個剝落 layout 輸入通道。推論時的 layout 由兩部分組成：面積來自纖維斷面力學時鐘 `hsp_P`，位置來自所有柱共用的重力模板（由下往上）。不用任何測試柱照片。

依據：[redesign/phase1_fiber_clock.md](redesign/phase1_fiber_clock.md)（時鐘、模板、v12 / v12basis）、`results/eval_suite/v12_compare/`、`results/eval_suite/v12gtrefiner/`。

## 結論（先講）

1. **訓練時給預測的 layout，模型會忽略 layout。** v12（OFP 形狀 + hsp_P）和 v12basis（重力模板 + hsp_P）把 layout 從 0 換成真值，剝落面積只變 0.01 左右。R307 在 8% 仍然畫成 0.42–0.47（真實 0.21）。
2. **訓練時給真值 layout（v12gt），推論時給重力模板 + hsp_P，兩根留出柱的剝落量都對了。** 高 DI 剝落偏差 CTR1 −0.006、R307 −0.019（v11app_sf 是 −0.056 / +0.062），KID 和 v11app_sf 相同（test 0.129 對 0.130）。
3. **加上 refiner（v12gtrefiner，6000 步）後，兩根柱的偏差都是 −0.001**，KID 和 app_r_6k 持平（test 0.087 對 0.090，val 0.028 對 0.025），演進 ratio 變好（test 0.53 → 0.61，val 0.76 → 0.89）。
4. **代價在紋理和裂縫。** 裂縫保留 0.66 → 0.53，沿用訓練柱程度（copy excess）大約變成兩倍，val 的損傷型態綜合偏差 1.44 → 1.99。
5. **v12gt 變得依賴 layout。** 不給 layout 時，它比 v11app_sf 更差（CTR1 −0.080）。所以 layout 不是可有可無的輔助輸入，推論時一定要給。

## 1. 動機

v11 之前的問題 4：生成器在沒看過的柱子上剝落量錯，CTR1 畫太少、R307 畫太多，兩根柱需要方向相反的修正。

- **條件端學不出來。** 4 根訓練柱（R315、R330、R615、R1015）的軸力、箍筋、斷面、f'c 都一樣，CTR1 與眾不同的參數在訓練資料裡是常數。不論是 GRU g、損傷狀態編碼器的 z，還是 Kalman 時鐘，都沒有一個能同時修好兩根柱（[phase0_clock.md](redesign/phase0_clock.md)、[kf_clock.md](redesign/kf_clock.md)、[DAMAGE_STATE_ENCODER.md](DAMAGE_STATE_ENCODER.md)）。
- **z 學的是力學損傷，不是剝落。** R307 在 8% 的強度比是 0.43，比 CTR1 的 0.66 掉得還多，但剝落少很多。
- **改用力學算。** 纖維斷面分析把 drift 換成混凝土應變，柱參數的作用由力學決定，不用從 4 根柱學。`hsp_P`（剝落高度）是第一個 CTR1、R307 修正方向都對的時鐘（layout 本身的面積偏差 CTR1 +0.001、R307 −0.037）。
- **為什麼要用 layout 通道。** 時鐘只決定「剝多少」。剝在哪裡，可以拆成所有柱共通的空間順序（由下往上）。用 layout 把面積和位置一起交給生成器，比再加一個全域標量更直接，也可以單獨檢查生成器有沒有照著畫。

## 2. 架構

### 2.1 生成器

和 v11_app 完全相同（ADM U-Net、conditional flow matching、`[z | 4 個損傷標量]` 走 gated 分支、8 維外觀碼、加載正負號），只多了一個空間輸入通道：

```
U-Net 輸入 = [ z_image | self_cond | coords | … | 物件 mask | layout ]
```

- layout 是 128 × 128 的截斷 SDF：剝落內為正、外為負，範圍 [−1, 1]。沒有剝落的幀全部是 −1，**全 0 代表「沒有 layout」**。
- layout 跟著影像一起做水平翻轉；patch 裁切也會一起裁到它。
- 從頭訓練，layout 通道使用預設初始化（不做 zero-init）。

### 2.2 時鐘：`hsp_P`

逐柱做單調彎矩–曲率分析：保護層和核心混凝土用 Mander 模型，鋼筋用雙線性。drift 換成柱底曲率 φ_b 用 Priestley, Calvi & Kowalsky (2007) 的塑鉸模型。保護層壓應變達 0.004 時的曲率記為 φ_sp，塑性曲率假設在塑鉸長度 L_p 內線性分布：

```
hsp_P = L_p · (φ_b − φ_sp) / (φ_b − φ_y)      單位 mm，每個迴圈峰值算一次，不遞減
```

輸入只有柱參數，以及到該幀為止的模擬迴圈，兩者推論時都已知。面積 A = f(hsp_P)，f 是只用 4 根訓練柱擬合的 isotonic 回歸。

### 2.3 位置：重力模板

- 模板 T：在 4 根訓練柱中剝落 > 3% 的幀上，統計每個 32 × 32 格子被剝的頻率，兩個柱面合併計算，再做左右對稱。
- 填格順序：依 T 由高到低填格子。T 相同的格子（頂部從未剝過的那些）底部優先，再用固定的隨機順序。所有柱、所有柱面共用同一個順序。
- 每一幀取順序最前的 round(A · 32²) 格，再轉成 128 的 SDF。結果是確定性的（K = 1），而且因為 A 不遞減，相鄰幀不會倒退。

先導比較（高 DI 幀和真值 iso32 的 IoU）：模板加 hsp_P 在 R307 是 0.359、CTR1 是 0.565。OFP 形狀加 hsp_P 是 0.196 / 0.528。所以 OFP 在面積之外沒有帶來額外的形狀資訊。

## 3. 流程

### 3.1 三種訓練 layout

| 版本 | 訓練柱的 layout | val（R307）的 layout | 步數 |
|---|---|---|---|
| v12 | OFP 形狀 + 樣本內 f(hsp_P) | OFP 形狀 + hsp_P | 15k，評估 14k |
| v12basis | 重力模板 + 樣本內 f(hsp_P) | 重力模板 + hsp_P | 15k，評估 14k |
| **v12gt** | **真值 iso32**（AnyLabel 剝落多邊形下採樣到 32） | 重力模板 + hsp_P | 15k，評估 10k |

三個版本都以 0.1 的機率把 layout 丟成 0。v12 和 v12basis 的想法是「訓練時看到的 layout 和測試時同一種，誤差也同一種」；v12gt 的想法是「訓練時給準確的 layout，讓模型學會照著畫」。

### 3.2 推論

```
柱參數 + 模擬迴圈 ─► 纖維斷面 ─► hsp_P ─► f ─► 面積 A
                                                  │
                    重力模板的填格順序 ───────────┴─► 32×32 覆蓋 ─► 128 SDF ─► layout 通道
v11 條件（z、損傷標量、加載正負號）、平均外觀碼 ─────────────────────────────► 全域條件
```

CTR1、R307 沒有自己的外觀碼，使用 8 個訓練碼的平均。測試柱的真值 layout 只用在 oracle 上限（`iso32`）。

### 3.3 Refiner

v12gtrefiner：v11 refiner 的配方（app_r），以 v12gt 第 10k 步為底模型兼 trunk 初始化，保留已訓練好的 layout 通道。state cache 由能讀 layout 的底模型產生，每一幀讀自己的 layout。上一幀用的是上一幀自己的 layout，和推論時一致。評估取第 6000 步，和 app_r_6k 相同。

### 3.4 評估時的 layout 輸入

| 名稱 | layout |
|---|---|
| none | 全 0（不給 layout） |
| hspP | OFP 形狀 + hsp_P 面積 |
| grav | 重力模板 + hsp_P 面積（**v12 的正式推論設定**） |
| iso32 | 測試柱的真值 layout（oracle 上限，不是可部署的設定） |

## 5. 判讀

- **（推論）layout 要在訓練時準確，模型才會依賴它。** v12 / v12basis 的訓練 layout 有誤差（面積 RMSE 約 0.05），而全域條件（z、損傷標量、外觀碼）在訓練柱上已經足以決定剝落量，所以模型走捷徑，不看 layout。v12gt 的訓練 layout 是真值，比全域條件更可靠，模型就改成照 layout 畫。推論時換成預測的 layout，面積誤差就直接傳到生成結果。
- **（量測）面積的修正幾乎全部來自時鐘。** grav 和 hspP 的面積相同、形狀不同，兩者在 CTR1 都接近 0。R307 的差別（−0.019 對 +0.029）來自形狀：OFP 形狀在 R307 比較分散，畫出來比較多。
- **（量測）形狀還差很遠。** IoU 0.35 對上限 0.49（單幀）、0.36 對 0.53（refiner）。重力模板抓不到 CTR1_NE 在 6% 的中段剝落。
- **（推論）裂縫和紋理的代價**，可能是模型更依賴 layout 之後，剝落區以外的細節改由訓練柱的樣子補上（copy excess 變大）。還沒有驗證。

## 6. 限制

- **hsp_P 用過測試柱。** 它是看了 CTR1 的偏差之後才注意到的，不是事先定的主時鐘。之後的模板、v12 系列都沒有再用 CTR1 選任何東西，但這個選擇本身用過 test。要完全排除這個疑慮，需要一根新的驗證柱。
- **v12gt 的 checkpoint（10k）是用 val KID（R307）選的**，所以 R307 的數字偏樂觀一點。v12 / v12basis 固定用 14k，refiner 固定用 6k。
- 驗證柱只有 2 根，CTR1 8% 只有 4 幀、R307 8% 有 6 幀。每個設定只有一個訓練 seed 和一個取樣 seed。
- 8% 的面積對剝落應變 ε_sp 很敏感：ε_sp = 0.003 時，CTR1 8% 會被低估（[phase1_fiber_clock.md](redesign/phase1_fiber_clock.md) §4）。
- v12gt 沒有 layout 就比 v11 差，所以推論流程一定要接上時鐘和模板。
- 剝落分割器只用訓練柱訓練、用 R307 選，R307 的量測可能偏樂觀一點。
