# 評估指標（定案版）

這份文件說明報告裡用到的每一個指標：它回答什麼問題、怎麼算、拿什麼當刻度、怎麼讀。結果見 [results.md](results.md)。指標的設計過程、試過但沒採用的做法，以及舊的數字，都在 [archive/](archive/)。

## 指標一覽

| 類別 | 指標 | 回答的問題 | 理想 |
|---|---|---|---|
| 真實感 | [KID](#kid) | 整體看起來像不像真實照片 | 低 |
| 條件一致性 | [演進 ratio](#損傷演進ratio-與-corr) | drift 變大時，損傷變化的幅度夠不夠 | 1 |
| | [演進 corr](#損傷演進ratio-與-corr) | 損傷隨 drift 變化的形狀對不對 | 1 |
| | [GT 鄰居對比](#gt-鄰居對比) | 每張圖是不是這個條件該有的樣子 | 高（以「另一根真實柱」為 100%） |
| 損傷內容 | [損傷面積](#損傷面積) | 高 DI 時剝落畫得夠不夠大 | 接近 GT |

| 多樣性 | [剝落面積 spread/skill](#剝落面積-spreadskill) | 同一條件的 K 張樣本，變化幅度有沒有反映不確定性 | 1 |

**最重要的一點：KID 不看條件。** 把生成圖隨機換到別的條件，KID 不變，所以 KID 只能回答「像不像真的」。條件有沒有畫對要看演進和鄰居對比，這兩個指標都通過打亂檢查：生成圖換到隨機條件後，分數會掉到約 0。

## 共同設定

### 資料切分

`Data/DamagePattern/id_list_val_R307.json`：

| split | 柱 | 張數 | 用途 |
|---|---|---|---|
| train | R615、R1015、R315、R330 | 533 | 訓練；也是抄襲指標的比對對象、像素門檻的校準來源 |
| val | R307 | 128 | 第二根留出柱，確認結論能不能重現 |
| test | CTR1 | 124 | 主要的留出柱 |

檔名格式 `CTR1_NE_06000_3.jpg`：柱、面（NE = Push、SW = Pull）、drift 代碼（06000 = 6%）、循環編號。cGAN 用的是舊切分 `id_list_old.json`，它的訓練集包含 R307，所以 cGAN 只在 test 上比。

### 參考集與影像域

參考集是 `Data/DamagePattern_inpaint_selfcondnoDI/images`：原始照片先把實驗器材補成混凝土，再做 CLAHE，最後存成 128×128、約 quality 75 的 JPEG。所有生成圖都要先轉到這個影像域，才能和參考集比：

| 模型 | 輸出的影像域 | 評估前的處理 |
|---|---|---|
| 本 repo 的模型 | CLAHE 後的灰階（訓練資料就是 CLAHE 後的圖） | JPEG q75 往返 |
| cGAN | 原始照片（它用 `Data/DamagePattern/images` 訓練） | 資料管線同一個 CLAHE（`dino_mmd.clahe_uint8`）→ 去干擾物並加 GT 遮罩對照 → JPEG q75 往返 |

- CLAHE 必須用資料管線本身的實作（`src/utils.py` 的 `ApplyCLAHE`），不能用 cv2 的：兩者的結果不同。cGAN 的平均亮度經 cv2 版是 201，經資料管線版是 162，而參考集（CTR1）是 159。
- cGAN 的去干擾物要在 CLAHE 之後做，因為干擾物偵測器和補圖模型都是在 CLAHE 域訓練的。cGAN 有 96% 的幀畫了干擾物；我們的模型約 0.3%，不做。
- JPEG 用在所有吃 DINOv3 特徵的指標，以及抄襲和多樣性指標。損傷型態和時序指標是像素統計，讀的是 JPEG 之前的樣本。
- 沒有轉到同一個影像域時，結論會被扭曲：cGAN 在 CLAHE 前的灰霧比例是 0.44（GT 0.09），裂縫的 copy excess 被低估成四分之一，都是對比太低造成的假象（[results.md](results.md#cgan-統一前處理前後)）。

### 不確定度

- **區塊 jackknife**：相鄰幀幾乎是同一張圖，把每個條件當成獨立樣本會讓 SE 低估約 2–2.5 倍。所以 SE 一律用 leave-one-block-out，一個區塊 = 同一面、同一 drift 級（test 22 個區塊，val 26 個）。
- **演進指標**以循環編號為單位做 jackknife。test 只有 7 個單位，z 要用自由度 6 的 t 分佈讀：z = 2 約 p ≈ 0.09，z = 3 約 p ≈ 0.02。
- **兩個模型怎麼比**：兩者共用同一組真實圖，直接對差值做配對 jackknife，報 z。配對差的 SE 約只有單一模型 SE 的一半。
- **K**：本 repo 的模型每個條件 8 張，cGAN 只有存檔的 1 張。需要 K > 1 的指標（spread/skill、1 − mask IoU）cGAN 沒有數值。

### 刻度

每個指標都附一個「真實柱能做到多少」的參考值，沒有刻度的數字無法解讀：

- **另一根真實柱**：test 上是 R307 對 CTR1，或其他柱在相同 DI 的真實照片。生成器不知道是哪一根柱，所以「換一根真實柱」能做到的，才是它可以追的目標。
- **訓練柱**：生成器學到的風格。
- **CTR1 自己**：抄襲門檻用 CTR1 校準。

## 真實感

### KID

**問題**：生成圖整體看起來像不像真實照片。

**算法**

1. 特徵：凍結的 DINOv3 ViT-S/16（`facebook/dinov3-vits16-pretrain-lvd1689m`），影像放大到 224，取 `[CLS ; patch 平均]`，768 維。
2. KID = 多項式核 `(xᵀy/d + 1)³` 的 MMD²（Bińkowski 2018），參考集是該 split 的真實圖。
3. 不偏的關鍵：真實圖 i 和從條件 i 生成的 K 張屬於同一組，所有核函數總和都排除同組的配對（block U-statistic）。不排除的話，「生成圖和自己的 GT」這種相依配對會讓模型看起來比實際好。

**刻度**：另一根真實柱（R307 對 CTR1）是 0.072。

**怎麼讀**：越低越好。不同 split 的 KID 不能比大小，因為 CTR1 離訓練集遠、R307 近。

程式：`scripts/eval/eval_dinov3_kid.py`，`dinov3_kid.json` 的 `kid_global`。

## 條件一致性

### 損傷演進（ratio 與 corr）

**問題**：drift 越大，生成圖有沒有越來越「不像沒損傷的樣子」？變化的量和形狀，有沒有跟 GT 一樣？

**算法**

1. 把每個面的圖依 drift 代碼分級，每一級算 DINOv3 特徵的中心。
2. 每一級的中心到最低一級中心的距離，連起來是一條演進曲線。GT 一條，每個模型各一條。
3. **ratio** = 模型曲線的總和 ÷ GT 曲線的總和，代表變化量是 GT 的幾成。
4. **corr** = 兩條曲線的 Pearson 相關，代表形狀像不像。
5. 兩個不能省的設計：
   - 最低一級不計入分數，否則任何曲線都會假裝和 GT 相關。
   - 中心距離用不偏估計（線性核 MMD² 的 U-statistic 再開根號）。直接用樣本平均會高估約 tr(Σ)/n，K = 1 的模型（每級的圖少）會白白佔便宜。

**刻度**：其他柱在相同 DI 的真實照片組成一條曲線，test 上 ratio 0.53、corr 0.83。CTR1 在 2% drift 就出現大量標記筆描線，曲線一開始就很高，所以連真實柱的 ratio 都只有 0.53；val（R307）上真實柱的 ratio 是 0.96。

**打亂檢查**：生成圖換到隨機條件後，ratio ≈ 0.05、corr ≈ 0。

程式：`dinov3_kid.json` 的 `progression_global`。

### GT 鄰居對比

**問題**：給定一個條件，生成圖是不是比較接近「GT 附近的真實圖」，而不是隨便哪張真實圖？

**算法**

1. 對每個條件 i，取 GT 的鄰居：同一根柱、同一面、DI 最接近的 4 張真實幀，不含 GT 本身。
2. 對比值 = 生成圖到「鄰居和 GT 以外所有真實圖」的平均距離 − 生成圖到鄰居的平均距離。減掉前一項等於扣掉整體真實感的落差，只留下和條件有關的部分。
3. K 張各算一次再平均。

**刻度**：每個條件從其他柱各取一張 DI 最接近的真實照片，算同樣的對比值，當作上限。報告的是「模型 ÷ 上限」，可以超過 100%：生成器看得到 CTR1 的條件，另一根柱看不到。

程式：`dinov3_kid.json` 的 `nbr_global`、`frac_of_ceiling`。

## 損傷內容

像素門檻都從訓練柱的完好幀（drift 代碼 ≤ 250，共 54 張）校準，不在 test 上調整。

### 損傷面積

**問題**：高 DI 時剝落畫得夠不夠大。

**算法**：每個像素用 7×7 視窗算兩個量：

- `d` = 局部平均亮度 − 表面亮度。表面亮度取上方 30% 列的中位數。
- `E` = 細紋理能量，即 |x − 高斯模糊(x)| 的局部平均。

依照這兩個量分類：
- **rough**：又暗又有細節，也就是露出的混凝土和鋼筋；
- **fog**：比表面暗，卻比完好混凝土還平滑，也就是灰霧；
- **white**：比任何完好表面都亮，也就是白塊。

損傷區 = 三類的聯集，損傷面積 = 損傷區占整張圖的比例，只看高 DI 三分位的條件。

**刻度**：GT（CTR1）0.164；訓練柱 0.131。

程式：`scripts/eval/eval_damage_texture.py`，`damage_texture.json` 的 `texture.high.damage_area`。

### 損傷型態綜合偏差

**問題**：損傷畫成了什麼樣子。DINOv3 指標只能說差多遠，不能說差在哪裡。

**算法**

1. 六個分項，各自只在有意義的條件上算：
   - 高 DI 三分位：損傷面積、灰霧占比、損傷區細紋理能量、白塊占比；
   - 每面最低 drift：提早出現的裂縫面積；
   - 低、中 DI：和訓練柱裂縫的最佳重疊。
2. 每項的 z =（模型 − GT）÷ 四根訓練柱之間的標準差。z = 1 代表「差了一根真實柱和另一根真實柱的典型差距」。
3. 綜合偏差 = 六個 z 的均方根。

**刻度**：四根訓練柱用同樣方式和 CTR1 比，中位數 1.20。低於這個值，代表和 CTR1 的差距在「換一根真實柱」的範圍內。

**怎麼讀**：均方根會被最大的那一項主導，分數高時要回頭看分項（`summary.md` 的損傷型態表）。這是診斷用的分數，各項權重相同是人為選擇。

程式：`damage_texture.json` 的 `composite`。

## 抄襲

抄襲只在內容層級認定，分裂縫和剝落兩種。兩者都用 train 的四根柱當比對對象，門檻都用 CTR1 真實圖校準：一根沒看過的柱，碰巧和訓練柱重疊的程度上限就在那裡。另附 R307（同樣沒看過的真實柱）的數值，標示「不抄」的合理範圍。

試過但不採用的全域做法：
- **DINOv3 全域特徵到訓練集的距離（Meehan 2020 的 copy 檢定）：** 一根沒看過的真實柱 R307，反而比任何模型都更靠近 train。這個量反映的是「像不像這個系列的柱子」，不是抄襲。
- **整張圖的像素最近鄰：** 會被格線和整體佈局帶動。
- **剝落形狀的 IoU：** 柱底剝落本來就是相似的帶狀區域。v12 的重力模板本身和訓練柱的重疊（0.72），還高於任何生成結果。

### 裂縫抄襲率

**問題**：裂縫是不是照搬某根訓練柱。

**算法**

1. 只看真實圖沒有剝落的條件：剝落分割器量到的面積 ≤ 0.02。
2. 裂縫圖（`crack_map`）：
   - 用 black-hat 取出細暗結構；
   - 去掉格線，也就是在某一列或某一行覆蓋率超過 55% 的結構；
   - 去掉小於 12 px 的點。
3. 每張樣本和 533 張訓練圖逐一算容許 3 px 的 F1，取最高值。這代表它最像哪一張訓練圖、像到什麼程度。
4. 門檻 = CTR1 真實圖做同樣計算的第 95 百分位。
5. 裂縫抄襲率 = 超過門檻的樣本比例。

**刻度**：CTR1 本身 5%（定義如此）；R307 約 22%。R307 和 R315、R330 同系列，裂縫型態本來就相近。

程式：`scripts/eval/eval_diversity.py`，`diversity_test.json` 的 `copy.copy_rate`；`best_match_column` 列出最佳配對來自哪根柱。

### 剝落內容抄襲率

**問題**：剝落區的碎塊、露筋、鋼筋形狀是不是照搬訓練柱。

**算法**

1. 剝落分割器（`phase0_layout_oracle_spallseg.py`）取出每張圖的剝落區，只看剝落面積 > 0.02 的圖。
2. 剝落區切成 16×16 的小塊：每 8 px 取一塊，至少 60% 在剝落區內，並排除標準差 ≤ 6 的平坦塊。
3. 每塊各自標準化後，在所有訓練幀的剝落塊（約一萬塊）裡找正規化相關係數（NCC）最高的一塊，不限位置。
4. 門檻 = CTR1 真實圖剝落塊的第 99 百分位。
5. 剝落內容抄襲率 = 超過門檻的小塊比例。

**刻度**：CTR1 本身 1%（定義如此）；R307 約 19%。

程式：`diversity_test.json` 的 `copy.spall_copy_rate`。

## 多樣性

### 剝落面積 spread/skill

**問題**：同一條件的 K 張樣本，變化幅度有沒有反映不確定性。

**算法**

1. 用剝落分割器量每張樣本和真實圖的剝落面積，只看真實剝落面積 > 0.02 的條件。
2. spread = K 張之間標準差的均方根；skill = K 張平均和真實值之間誤差的均方根。
3. spread/skill = √((K+1)/K) × spread ÷ skill（GenCast，Price et al. 2024）。

**怎麼讀**：1 代表校準良好；小於 1 代表樣本彼此太一致，卻又常常猜錯。附帶的 rank histogram 看真實值在 K 張樣本裡排第幾：集中在兩端代表真實值常落在樣本範圍之外，期望比例是 2/(K+1) = 0.22。

程式：`diversity_test.json` 的 `spread`。

### 同條件內 1 − mask IoU

**問題**：同一條件的 K 張樣本，剝落形狀彼此有多不同。

**算法**：K 張樣本的剝落遮罩兩兩算 IoU，取平均，報 1 − IoU。兩張遮罩聯集小於 50 px 的配對不算。

**刻度**：
- 同一根柱、同一 drift 和循環的**另一面**是上限，0.89；
- **同一面的下一圈**是近乎重複的下限，0.72。

程式：`diversity_test.json` 的 `within.mask_1_minus_iou`。

## 時序

一條軌跡 = 一根柱、一個面在該 split 的所有幀，依時間排序。把各幀的第 k 張樣本串起來，就是第 k 條生成軌跡。單幀模型的軌跡等於隨機配對，這正是拿單幀模型去生成序列時會得到的結果。

### 損傷倒退

**算法**：相鄰幀之間，損傷面積（損傷面積那一節的像素分類）下降超過 20%、且至少 50 px 的比例。

**刻度**：GT 0.12。真實損傷不會癒合，只有碎塊掉落會造成倒退。

程式：`scripts/eval/eval_temporal.py`，`temporal.json` 的 `regress`。

### 變化量比

**算法**：模型相鄰幀的平均灰階差 ÷ 同一對 GT 相鄰幀的平均灰階差。

**怎麼讀**：1 代表變化和照片一樣多；遠大於 1 是閃爍，遠小於 1 是畫面凍住。一條完全不動的軌跡，倒退率也會很低，所以這兩個指標要一起看，並搭配演進 ratio。

程式：`temporal.json` 的 `flicker_ratio`。

## 不放主表的數字

以下仍會輸出在 `summary.md` 或 json 裡，但不拿來下結論：

| 數字 | 原因 |
|---|---|
| patch KID | 排名和 KID 一樣 |
| R_spall probe R²、高剝落讀數 | 和損傷面積重疊 |
| 飽和幀 | 目前所有模型都在 0–2%，沒有鑑別力 |
| 灰霧、白塊、極暗、細紋理的分項 | 已合進綜合偏差；分項放在 `summary.md` |
| copy excess | 和裂縫抄襲率重疊，而且沒有「不抄」的刻度 |
| density / coverage / 落在之外 | 只有一根 test 柱，coverage 幾乎都是 0；「之外」會把沒看過的外觀和畫壞混在一起 |
| Vendi、cos 距離 | 和 1 − mask IoU 重疊 |
| 色調跳動、結構閃爍、損傷保留、裂縫保留 | 時序分項，放在 `summary.md` |
