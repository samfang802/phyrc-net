# 損傷型態的像素統計

**它回答**：模型畫的是哪一種損傷。DINOv3 指標只能說差多遠，不能說差在哪裡。

這裡把目視常見的三種失敗變成數字：

| 目視現象 | 量測 |
|---|---|
| 高 DI 時畫成灰霧，不是剝落 | `fog_share`、`E_damage` |
| 剝落區裡有很多白塊 | `white_share`、`white_blobs`、`blob_size` |
| 低 DI 時沿用訓練柱的裂縫 | `before_loading`、`copy_excess`、`nn_specimen` |

這些量最後合成一個綜合分數，見[綜合分數](#綜合分數損傷型態偏差)。

程式：`src/metrics/damage_texture.py`、`scripts/eval/eval_damage_texture.py`，輸出 `damage_texture.json`。

**所有門檻都從訓練柱的完好幀校準**：drift 代碼 ≤ 250 的幀，共 54 張，取它們的百分位數。不在 test 上調整。實際門檻值會寫在輸出的 `thresholds` 裡。

## 像素分類

每個像素用 7×7 的視窗計算兩個量：

- `d` = 局部平均亮度 − 這張圖的表面亮度。表面亮度取上方 30% 列的中位數，那一帶在這批資料裡都還完好。這樣整張圖偏暗或偏亮，不會被當成損傷。
- `E` = 細紋理能量，即 |x − 高斯模糊(x, σ=1)| 的局部平均。真實的剝落有碎石和鋼筋，E 高；灰霧很平滑，E 低。

| 類別 | 條件 | 代表 |
|---|---|---|
| rough | d < 完好幀的 p0.5，且 E ≥ 完好幀的中位數 | 又暗又有細節：露出的混凝土、鋼筋 |
| fog | d < 完好幀的 p5，且 E < 完好幀的中位數 | 比表面暗，卻比完好混凝土還平滑：灰霧 |
| white | d > 完好幀的 p99.5 | 比任何完好表面都亮：白塊 |

損傷區 = rough ∪ fog ∪ white。

| 輸出鍵 | 意義 |
|---|---|
| `damage_area` | 損傷區占整張圖的比例 |
| `fog_share`、`white_share` | 損傷區中灰霧、白塊各占多少 |
| `black_share` | 損傷區中比表面暗、超過完好像素 p0.1 的像素比例（極暗的塗抹） |
| `white_blobs`、`blob_size` | 白塊的個數（≥ 4 px）與平均面積 |
| `E_damage` | 損傷區的平均細紋理能量 |

各占比都需要先有一塊損傷區，至少 50 px，才有定義。所以**占比類的量只看高 DI 三分位**；低 DI 的損傷區只有幾十個像素，占比是雜訊。

每個量都報三組數字：

- 模型的數值；
- GT 的數值；
- 配對差（`diff` = 模型 − GT，逐條件配對）。

SE 是區塊 jackknife。參考列：

- **訓練柱**（同一個 DI 區間）：生成器學到的風格。
- **另一根真實柱**（`--other_split`，預設 R307）。

## 裂縫

**裂縫圖**（`crack_map`）

1. 用 black-hat（closing − 原圖）取出細暗結構。
2. 去掉畫的格線：在某一列或某一行覆蓋率超過 55% 的就是格線。格線是直的，會集中在 1–2 列；裂縫是彎的，會分散在很多列。
3. 去掉小於 12 px 的點。

**比較**（`crack_f1`）：兩張裂縫圖之間的 F1，容忍度 3 px。也就是「A 的裂縫像素有多少落在 B 的裂縫 3 px 以內」，反過來也算，再取調和平均。

只在低和中 DI 的條件上計算，因為這時還沒有剝落，畫面主要就是裂縫。

| 輸出鍵 | 意義 |
|---|---|
| `f1_gt` | 生成圖和自己 GT 的 F1 |
| `f1_train_max` | 生成圖和 533 張訓練圖中最像的那張的 F1 |
| `copy_excess` | 模型的 `f1_train_max` − GT 自己的 `f1_train_max` |
| `nn_specimen` | 最像的訓練圖來自哪根柱 |
| `crack_area_diff` | 裂縫面積的配對差 |
| `before_loading` | 每個面最低 drift 那一級的裂縫面積。真實柱在這一級幾乎沒有裂縫 |

**怎麼判斷沿用了訓練柱**：一根真實但沒看過的柱，本來就會和訓練柱碰巧重疊一些，因為大家都是水平的撓曲裂縫。所以要看**超出量**：模型和訓練圖的重疊，比 GT（以及另一根真實柱）和訓練圖的重疊多出多少。如果還同時有 `before_loading` 偏高，也就是條件說沒損傷卻畫了裂縫，就是「不管條件都畫一套訓練柱的裂縫」。

## 白塊會不會讓 DINOv3 低估演進距離（`--dino`）

**想法**：同一個條件的 K 張圖，白塊有多有少。如果白塊會讓 DINOv3 覺得「比較沒損傷」，那同一條件內白塊多的那幾張，到「最低 drift 中心」的距離應該比較短。

**作法**

1. 對每張圖，計算它到自己模型同一面最低 drift 級中心的 DINOv3 距離。這就是演進指標加總的那個量。
2. 每個變數都在條件內扣掉平均（去除條件本身的影響），再把距離對白塊面積做迴歸，同時控制損傷面積和灰霧。
3. 只用高 DI 三分位。係數的 SE 用區塊 jackknife。

**輸出**

| 鍵 | 意義 |
|---|---|
| `coef_white` | 白塊係數。負值且顯著，表示白塊讓圖看起來比較沒損傷 |
| `gap_gt_minus_model` | 高 DI 時，GT 比模型離最低中心多遠 |
| `explained_gap` | 係數 ×（模型白塊 − GT 白塊），也就是這段差距中可以歸給白塊的部分 |

需要 K > 1，所以 K = 1 的模型（例如 cGAN 存檔圖）會跳過這一項。

## 綜合分數：損傷型態偏差

把上面各項合成一個數，越低越好。輸出在 `damage_texture.json` 的 `composite`，圖在 `damage_texture_score.png`。

**組成**：六項，各自只在有意義的條件上計算。

| 項目 | 條件範圍 | 抓的是 |
|---|---|---|
| `damage_area` | 高 DI 三分位 | 剝落畫得夠不夠大 |
| `fog_share` | 高 DI 三分位 | 灰霧 |
| `E_damage` | 高 DI 三分位 | 損傷區有沒有細節 |
| `white_share` | 高 DI 三分位 | 白塊 |
| `early_cracks` | 每個面最低 drift 那一級 | 還沒加載就畫裂縫 |
| `copy` | 低＋中 DI | 和訓練柱裂縫的最佳重疊 |

**計算**

1. 每一項先算 z = (模型的值 − GT 的值) ÷ 訓練柱之間的標準差。
   - 「訓練柱之間的標準差」= 4 根訓練柱各自算出這一項，取它們的標準差。所以 z = 1 代表「差了一根真實柱和另一根真實柱的典型差距」。
   - 訓練柱的 `copy` 用留一柱的方式算：這根柱的裂縫和其他 3 根柱比。
2. 綜合分數 = 六個 z 的均方根（RMS）。
3. SE 用 test 的區塊 jackknife，柱間標準差固定不動。模型之間做配對比較。

**刻度**：把 4 根訓練柱也用同樣的方式和 GT 比，得到「一根真實柱」的分數（中位數約 1.2）。模型的分數低於這個值，表示它的損傷型態和 CTR1 的差距，在「換一根真實柱」的範圍內。

**怎麼讀**

- z 有正負號：負的是畫得太少，例如損傷面積不足；正的是太多，例如灰霧、提早出現的裂縫。圖的左欄是每一項的 z，灰色帶是 4 根訓練柱的範圍；右欄是綜合分數。
- 均方根會被最大的那一項主導。分數高的時候，要回到左欄看是哪一項造成的。
- 這是一個**診斷用**的分數，用來說明「損傷畫成了什麼樣子」。各項權重相同，是人為選擇；它不能取代條件指標，也還沒和人的判斷比對過。

## 限制

- 門檻是像素層級的手工定義，分不出「白色混凝土碎塊」和「白色塗漆」，也分不出白塊的形狀。目視上「假白塊」的特徵可能是圓、邊緣銳利、旁邊是黑色塗抹，這些都沒有被量到。要量形狀，需要標一小批資料訓練分類器，或改用圓度、邊緣銳利度這類描述量。
- 補圖會在干擾物的位置留下亮塊。R307 低 DI 的大量 white 就是這個，不是剝落，所以那一列的占比不能用。
- 裂縫圖會殘留少量格線碎段，CTR1 的標記筆文字也會被當成裂縫。兩邊都一樣處理，所以比較仍然公平，但絕對值不要解讀成真實的裂縫面積。
